Who goes first? How programs find the next job without sorting anything

Data Structures and Algorithms

A game sets a timer for every enemy on screen. A server receives requests faster than it can answer them. A search engine compares your question with millions of documents and shows you ten. New items keep arriving, and every time the program needs just one thing: the next one.

So the question is: how do you always have the smallest item at hand, when the items never stop changing? Sorting everything again after each change is far too slow. A heap keeps only the order it needs: the smallest item on top.

The next job

  • Inside Go. The runtime of the Go language keeps the timers of each processor in a heap, ordered by the moment each one fires. It is not a binary heap: every node has four children.[1]
  • Inside AI servers. vLLM, an open-source server that runs language models, can serve requests by priority. Waiting requests go into a heap: the lowest priority value is served first, and ties go to the request that arrived earlier.[2]
Use a heap when you only ever need the next item, and new items keep arriving.

The best few, without sorting everything

  • In Python. The standard module heapq has nlargest and nsmallest. Its documentation says they work best when you ask for few items; for many, sorting is better.[3]
  • In vector search. FAISS, Meta's library for finding the vectors closest to a query (the kind of search an AI assistant uses to look up documents), ships its own heap functions, "tailored for efficient similarity search".[4]
To keep the k best of a long stream, keep a heap of size k, not a sorted list of everything.

Did you know?

The binary heap was first described by J. W. J. Williams in 1964, together with heapsort. The same year, Robert Floyd showed how to build a heap from N items in linear time.[5]

Think about it

  1. A heap finds the smallest item at once, but it cannot quickly find any other item. Why might that be enough?
  2. To keep the 10 largest numbers of a stream, should the heap put the largest or the smallest of the 10 on top?
  3. Why might a tree with four children per node beat one with two?
