Who goes next? Stacks, queues, deques and priority queues in the software you use

Data Structures and Algorithms

You have probably used all four of the structures in this reading today. You pressed Back on your phone, a video kept loading a few seconds ahead of what you were watching, a message arrived in the order it was sent, and somewhere a hospital attended the most serious patient first, not the one who arrived first.

Each of those systems answers the same question: which element leaves next? The answer is the whole difference between a stack, a queue, a deque and a priority queue.

Stacks: undo the last thing

  • The Back button. Android keeps the screens you open in a back stack: a new screen is pushed on top, and Back pops it to reveal the previous one — "a last in, first out object structure", in the words of its documentation.[1]
  • Every program you run. Each function call pushes a frame on the call stack, and returning pops it.[2] A recursion that never stops keeps pushing until the stack runs out of space: a stack overflow.[3]
Use a stack when the most recent item is the one you need back first.

Queues: first come, first served

  • The web page you are reading. JavaScript in the browser takes pending work from a queue: it runs one job completely, then pulls the next one, oldest first.[2]
  • Buffers everywhere. Your operating system moves data between devices and programs through circular buffers: a fixed array where the producer writes at the head and the consumer reads at the tail.[4]
Use a queue when fairness means "in the order it arrived".

Deques: both ends open

  • "Keep only the last N." Python's deque with a maximum length drops the oldest item from the other end when it is full — useful when only the most recent activity matters.[5]
  • Sharing work between processor cores. In work stealing, each core keeps its tasks in a deque: it works at one end, and an idle core steals from the other.[6] Java's ForkJoinPool works this way.[7]
Use a deque when you need to add or remove at both ends.

Priority queues: the most urgent first

  • Maps and navigation. Dijkstra's shortest-path algorithm repeatedly takes the closest place not yet visited, and it does that with a priority queue.[8]
  • Your CPU. The Linux scheduler decides which program runs next. Its newest version picks the task with the earliest deadline;[9] its predecessor, CFS, kept every runnable task in a red-black tree — a balanced binary search tree — and always ran the leftmost one.[10]
Use a priority queue when importance, not arrival time, decides who goes next.

Did you know?

These ideas are older than personal computers. Alan Turing already used a stack in 1946 to call and return from subroutines, with the words bury and unbury.[11] And the mathematics of waiting lines started in 1909, when Agner Erlang studied calls at the Copenhagen Telephone Company.[12]

Think about it

  1. You open screens A → B → C on your phone and press Back twice. Which screen do you see, and why does a stack give that answer without searching?
  2. A queue lives in an array of 5 slots. After several enqueues and dequeues, the back has reached the last slot, but slots 0 and 1 are free. What would you do so the next element can still enter?
  3. In an emergency room, why would a plain queue be dangerous? What must the structure know about each patient that a queue ignores?
