12.1 · Trees

A binary tree: a root and two subtrees

  • In a binary tree no node has more than two children. A binary tree is either empty, or a root with a left subtree and a right subtree.

struct Node {
    int info;        // the value
    Node* left;      // root of the left subtree, or nullptr
    Node* right;     // root of the right subtree, or nullptr
};
Checkpoint

A tree is a root with two children, and both children are leaves. With the definitions of this course, what are the height of the tree and the depth of the leaves?

B. The longest path from the root down to a leaf has one edge, so the height is 1; one edge separates the root from each leaf, so their depth is 1. A counts nodes instead of edges: some books do (there a leaf has height 1), but here a leaf has height 0. C starts the depths at 1, but the root is at depth 0.

12.2 · Traversals

Three orders: when do you visit the root?

Traversal1st2nd3rd
Preorderrootleft subtreeright subtree
Inorderleft subtreerootright subtree
Postorderleft subtreeright subtreeroot
  • A traversal visits every node exactly once. "Visit" means do something with the node: print it, count it, delete it.
  • Left always goes before right. Each subtree is traversed with the same rule, so the code is recursive.

12.2 · Traversals

Three lines of recursion; only the visit moves


void inorder(Node* n) const {
    if (n == nullptr) return;        // empty subtree: nothing to do
    inorder(n->left);                // 1. the left subtree
    std::cout << n->info << " ";     // 2. the root
    inorder(n->right);               // 3. the right subtree
}
  • This is inorder. Line 4 first gives preorder; line 4 last gives postorder.
  • Postorder with delete n instead of the print frees a whole tree.
Every traversal visits each node once: O(n).
Checkpoint

A binary tree has root 5. Its left child is 3, with children 1 and 4; its right child is 8. Which traversal prints 1 4 3 8 5?

A. In postorder the root 5 is last, and 3 comes right after its children 1 and 4. Inorder prints 1 3 4 5 8, with the root between its subtrees. Preorder prints 5 3 1 4 8, with the root first.

12.3 Search and insertion

12.3 · Search and insertion

Smaller to the left, greater to the right

  • A binary search tree (BST) is a binary tree with an order rule: at every node, all the values in its left subtree are smaller than the node, and all the values in its right subtree are greater.
  • That is why inorder printed 70, 143, 178, … in ascending order: left subtree, root, right subtree is "smaller, me, greater".
  • In our examples, values do not repeat.
At each node, the order rule tells you which subtree you can ignore.

12.3 · Search and insertion

Search: one comparison, one step down


// struct Node { int info; Node* left; Node* right; };
// class BST, private member: Node* root = nullptr;
Node* search(Node* n, int x) const {          // private, recursive
    if (n == nullptr) return nullptr;         // fell off: not found
    if (x < n->info) return search(n->left, x);
    if (x > n->info) return search(n->right, x);
    return n;                                 // equal: found
}
Node* search(int x) const { return search(root, x); }   // public
  • The public method takes only the value; the private one also carries the root of the subtree it is looking at.
  • It returns a pointer to the node, so the caller can use what is stored there.
12.3 · Search and insertion

Insert = search until you fall off the tree

12.3 · Search and insertion

Insert: the null link becomes the new node


bool insert(Node*& n, int x) {            // n: a reference to a link
    if (n == nullptr) {                   // free spot found
        n = new Node{x, nullptr, nullptr};
        return true;
    }
    if (x < n->info) return insert(n->left, x);
    if (x > n->info) return insert(n->right, x);
    return false;                         // repeated value: rejected
}
bool insert(int x) { return insert(root, x); }   // public
  • n is not a copy: it is the tree's own pointer (root, or some node's left or right), so n = new Node connects the new node to the tree. Without the &, the tree would not change.

Why Node*&: a pointer is a slip of paper with an address on it; the node is the house.

  • By value = a photocopy: good enough to go to the house and paint it (n->info = 5). If you write a different address on the photocopy (n = new Node), the original does not change.
  • By reference = the original slip.
  • Key case: an empty tree. root says "no address", and insert has to write the address of the new node there.
  • Question for the class: will the function write a new address on the caller's slip? Yes → Node*&. No → Node*.
Checkpoint

You insert 50, 30, 70 and 60 into an empty BST, in that order. Then you insert 65. Where does it go?

C. 65 > 50 → right; 65 < 70 → left, where 60 already is; 65 > 60 → right, a null link. A stops one step early: the left link of 70 is taken by 60, and insert never replaces a node. B fills the first free link it sees, but 65 is greater than 50, so it can never be in the left subtree of 50.

12.4 · Deletion

Remove: find the node, then pick the case


bool remove(Node*& n, int x) {
    if (n == nullptr) return false;                  // not found
    if (x < n->info) return remove(n->left, x);
    if (x > n->info) return remove(n->right, x);
    if (n->left != nullptr && n->right != nullptr) { // two children
        n->info = findMin(n->right)->info;           // copy the successor
        return remove(n->right, n->info);            // delete it below
    }
    Node* old = n;                                   // leaf or one child
    if (n->left != nullptr) n = n->left;             // the left child moves up
    else n = n->right;                               // the right child, or nullptr
    delete old;
    return true;
}
  • Line 11 also covers a leaf: there n->right is null, so the link becomes null.
  • Where is the new? In insert: every node of the tree was created there.
  • The BST class creates the nodes, so the BST class frees them: one delete for each new.
  • Without delete old, the node is out of the tree but still uses memory: a leak.
12.4 · Deletion

findMin: keep going left


Node* findMin(Node* n) const {                   // n is not null
    while (n->left != nullptr) n = n->left;      // go left to the end
    return n;                                    // smallest value of the subtree
}
  • Called on the right subtree, it returns the successor. The second remove then deletes that value from the right subtree: a leaf or a one-child case.
  • The price: two walks down the same path. Weiss accepts it to keep the code short.
  • Without delete old the node leaks: C++ has no garbage collector.
  • Two walks: only when the node has two children (lines 6 and 7 of remove).
  • Walk 1: findMin reads the successor. Walk 2: remove goes down the same path to delete it. Example: 70, 60, 55, twice.
  • Still O(height). Weiss keeps it for simplicity; a removeMin method would do it in one pass.
Checkpoint

A BST is built by inserting 50, 30, 70, 20, 40, 60 and 80. You call remove(50) with the code of this session. Which value ends up in the root?

B. 50 has two children, so the code copies findMin of the right subtree: right once to 70, then left to the end, 60. A is the mirror rule, the predecessor: it also leaves a valid BST, but it is not what this code does. C would need 70 to adopt 30 as its left child, but 70 already has 60 there.
The cost

Same seven keys, two very different trees

  • Search, insert and remove follow one path from the root: at most height + 1 nodes. Finding 9 takes 3 comparisons on the left and 7 on the right.
  • With n nodes the height can be anything from ⌊log₂ n⌋ to n − 1, and the insertion order decides. Keeping it small is the job of the AVL tree.

Why it matters today

One path from the root, inside AI systems

  • Decision trees: each node compares one feature with a threshold and goes left or right. A prediction is one path from the root, so its cost is the depth of the tree, as in a BST search.
  • Nearest neighbors: a k-d tree is a binary tree that splits the points along one coordinate axis per node. In few dimensions, it finds the closest point without comparing against all N.
STL

std::set: sorted keys in O(log n)


std::set<int> s = {710, 689, 2000, 143};
s.insert(1500);                              // O(log n)
if (s.count(689) == 1) std::cout << "found\n";
for (int x : s) std::cout << x << " ";       // 143 689 710 1500 2000
auto it = s.lower_bound(700);                // first key >= 700
std::cout << *it;                            // 710
  • Search, insertion and removal are O(log n). It is usually implemented as a red-black tree, a BST that keeps itself short.
  • Iterating visits the keys in ascending order: an inorder traversal.
