The problem

Visit every vertex once, and only once

  • A tree has no cycles, so a traversal never comes back.
  • A graph can have cycles: without care, you walk in circles forever.
  • The fix: mark each vertex the first time you reach it.
DFS and BFS differ in one thing only: which vertex they visit next.

17.1 BFS: breadth-first search

First the close vertices, then the far ones.

17.1 · BFS

Visit in layers, like ripples in water

  • Start at s. Distance 0.
  • Then every vertex at distance 1, then at distance 2, …
  • A queue keeps the order: first in, first out.
  • On a tree, this is level-order traversal.
BFS finds the shortest path in number of edges.

17.1 · BFS

BFS in code: a queue and a distance per vertex


std::vector<int> bfs(const ListGraph& g, int n, int s, std::vector<int>& parent) {
    std::vector<int> dist(n + 1, -1);      // -1: not discovered (Weiss: ∞)
    parent.assign(n + 1, 0);
    std::queue<int> q;
    dist[s] = 0; q.push(s);
    while (!q.empty()) {
        int v = q.front(); q.pop();
        for (int w : g.neighbors(v))
            if (dist[w] == -1) {           // first time we see w
                dist[w] = dist[v] + 1;
                parent[w] = v;             // came from v (Weiss: path)
                q.push(w);
            }
    }
    return dist;
}
17.1 · BFS

parent gives you the path back


void printPath(const std::vector<int>& parent, int s, int v) {
    if (v != s)
        printPath(parent, s, parent[v]);   // first, the way to the vertex before v
    std::cout << v << " ";                 // then v itself
}
  • From 3 to 7: parent[7] = 4, parent[4] = 1, parent[1] = 3.
  • It prints 3 1 4 7: 3 edges, the shortest.

17.2 DFS: depth-first search

Go as deep as you can, then back up.

17.2 · DFS

Go deep first, back up when stuck

  • Visit v and mark it.
  • Take its first unmarked neighbor, and repeat from there.
  • No unmarked neighbor left? Go back one step.
  • It is preorder, made safe for cycles (Weiss, § 9.6).
Like searching your folders: open one, go to the bottom, then come back up.

17.2 · DFS

DFS in code: recursion does the backing up


void dfs(const ListGraph& g, int v,
         std::vector<bool>& visited, std::vector<int>& order) {
    visited[v] = true;                     // mark it before going on
    order.push_back(v);                    // visit v first (preorder)
    for (int w : g.neighbors(v))
        if (!visited[w])
            dfs(g, w, visited, order);     // go deep along w
}
  • The call stack remembers where to go back.
17.2 · DFS

Some vertices are not reachable: start again


std::vector<int> dfsAll(const ListGraph& g, int n) {
    std::vector<bool> visited(n + 1, false);
    std::vector<int> order;
    for (int v = 1; v <= n; ++v)
        if (!visited[v])           // not reached yet?
            dfs(g, v, visited, order);   // new tree
    return order;
}
  • Each new start builds one tree. All together: a DFS forest.
  • Undirected graph: one tree means it is connected.

Same loop, different container


std::queue<int> todo;
todo.push(s);
while (!todo.empty()) {
    int v = todo.front(); todo.pop();
    if (visited[v]) continue;
    visited[v] = true; order.push_back(v);
    auto& nb = g.neighbors(v);
    for (int i = 0; i < (int)nb.size(); i++)
        if (!visited[nb[i]]) todo.push(nb[i]);
}
      

std::stack<int> todo;
todo.push(s);
while (!todo.empty()) {
    int v = todo.top(); todo.pop();
    if (visited[v]) continue;
    visited[v] = true; order.push_back(v);
    auto& nb = g.neighbors(v);
    for (int i = (int)nb.size() - 1; i >= 0; i--)
        if (!visited[nb[i]]) todo.push(nb[i]);
}

Only the highlighted lines change. Neighbors go in backwards, so the stack gives the first one first.

Both mark v when popped, so v may enter twice. Stack: de la Cueva et al. (2020), § 10.3.2.

17.3 Topological sort

Put the tasks in an order that respects every arrow.

17.3 · Topological sort

An order where every arrow points forward

  • Edge v → w means "v before w": a prerequisite.
  • A topological order puts v before w, for every edge.
  • A cycle makes it impossible: v before w and w before v.
  • The order is not unique. Any valid one is fine.

Weiss (2014), § 9.2: his example is a map of course prerequisites.

17.3 · Topological sort

Take a vertex with no prerequisites, repeat

Weiss (2014), Fig. 9.4–9.7, on the graph of P16. A vertex enters the queue when its in-degree reaches 0.

17.3 · Topological sort

Topological sort in code (Kahn's algorithm)


std::vector<int> topsort(const ListGraph& g, int n) {
    std::vector<int> indeg(n + 1, 0), order;
    for (int v = 1; v <= n; ++v)
        for (int w : g.neighbors(v)) ++indeg[w];
    std::queue<int> q;
    for (int v = 1; v <= n; ++v)
        if (indeg[v] == 0) q.push(v);      // no prerequisites
    while (!q.empty()) {
        int v = q.front(); q.pop();
        order.push_back(v);
        for (int w : g.neighbors(v))
            if (--indeg[w] == 0) q.push(w);   // w is free now
    }
    if ((int)order.size() != n) throw std::runtime_error("the graph has a cycle");
    return order;
}

Weiss (2014), Fig. 9.7. If the queue empties too early, there is a cycle.

17.3 · Topological sort

Topological sort is O(V + E)

  • Counting in-degrees reads every list once: O(V + E).
  • Each vertex enters and leaves the queue once: O(V).
  • Each edge lowers one in-degree once: O(E).
Total: O(V + E). The simple version that scans for in-degree 0 is O(V²).

Weiss (2014), § 9.2.

Checkpoint

You run Kahn's algorithm on the edges 1→2, 2→3, 3→1 and 3→4. What happens?

A. Correct. Every vertex has in-degree 1, so the queue starts empty. The order has 0 vertices, not 4: a cycle.

B. 1 can never go first: 3 → 1 is a prerequisite that never disappears.

C. Kahn never follows a cycle. A vertex enters the queue at most once, so it always stops.

Topological sort with DFS and a stack


void dfsTopo(const ListGraph& g, int v,
             std::vector<bool>& visited, std::stack<int>& done) {
    visited[v] = true;
    for (int w : g.neighbors(v))
        if (!visited[w])
            dfsTopo(g, w, visited, done);
    done.push(v);                          // everything after v is finished
}
// Call it from every unvisited v. Then pop the stack: that is the order.
  • A vertex goes on the stack when all its successors are done.
  • On P16's graph it gives 1 2 5 4 3 7 6, the other order in Weiss.

de la Cueva et al. (2020), § 10.4.3. This version does not detect cycles.

Self-study

Deep recursion can crash your DFS

  • Each recursive call uses space on the call stack.
  • A path of a million vertices means a million nested calls.
  • That can overflow the stack, and the program crashes.
  • Big graphs: use the version with std::stack.
Self-study

Python has a topological sort built in


from graphlib import TopologicalSorter
# each node maps to its prerequisites
ts = TopologicalSorter({"D": {"B", "C"}, "C": {"A"}, "B": {"A"}})
print(list(ts.static_order()))     # one valid order: A first, D last
  • Since Python 3.9. A cycle raises graphlib.CycleError.
Why it matters today

DAGs inside AI systems

  • Training: PyTorch records each operation in a DAG.
  • To get gradients, it traces that DAG from the output back to the inputs.
  • Each gradient must be ready before it is used: that is a topological order.
