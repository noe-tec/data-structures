The problem

Restricting access is a feature

  • A vector or a linked list lets you touch any position. Many problems only ever need one or two ends.
  • Fewer operations means each one can be O(1), and the code cannot misuse the data by accident.
  • Today: four structures defined by which element leaves next — the newest (stack), the oldest (queue), either end (deque), the most urgent (priority queue).
The access rule is the data structure. Array or linked list is only how you store it.

11.1 Stack

11.1 · Stack

Only the top is visible

  • A stack inserts and removes at the same end, the top. The last element in is the first one out: LIFO.
  • push(x) puts x on top · pop() removes the top · getTop() reads it without removing it.
  • Like a pile of plates: you add and take from the top, never from the middle.
push and pop only touch the top, so neither depends on how many elements are below.
11.1 · Stack

Seven operations on an array of five

11.1 · Stack

Stack on a fixed array


// members: static const int MAX = 5;  int data[MAX];  int top = -1;
bool push(int x) {
    if (top == MAX - 1) return false;   // full: x is lost
    data[++top] = x;
    return true;
}
bool pop() {
    if (top == -1) return false;        // empty
    --top;                              // no need to erase
    return true;
}
int getTop() const { return data[top]; }   // caller checks first
  • top = -1 means empty. data[++top] = x: first move top, then write.
  • A full stack rejects x instead of writing out of bounds.
11.1 · Stack

Stack on a linked list: the head is the top


// struct Node { int info; Node* next; };
// member: Node* head = nullptr;         (the head is the top)
void push(int x) { head = new Node{x, head}; }
bool pop() {
    if (head == nullptr) return false;  // empty
    Node* old = head;
    head = head->next;
    delete old;
    return true;
}
int getTop() const { return head->info; }
~ListStack() { while (pop()) {} }       // free every node
  • push inserts before the head and pop deletes the head: both O(1), and there is no capacity limit.

Checkpoint

You build a stack on a singly linked list that keeps only a head pointer. Where should push and pop work?

C. At the head, both operations change one pointer. A fails because removing the tail of a singly linked list needs the node before it, and finding it is an O(n) walk — even with a tail pointer. B confuses capacity with cost: unlimited size says nothing about how expensive each end is.

11.2 Queue

11.2 · Queue

Enter at the back, leave at the front

  • A queue inserts at one end (the back) and removes at the other (the front). The first element in is the first one out: FIFO.
  • enqueue(x) adds at the back · dequeue() removes the front · getFront() reads it.
  • Like the line at a supermarket checkout: arrival order is service order.
A queue needs two ends, so an implementation must make both of them O(1).
11.2 · Queue

Two ends, two jobs

  • front marks the next element to leave; back marks the last one that entered.
  • Here dequeue() removes the 5, and enqueue(x) places x right after the 8.

11.2 · Queue

Why a plain array does not work

  • Shift on dequeue: move every element one slot left. Correct, but each dequeue is O(n).
  • Move the front index instead: O(1), but front and back drift right. After 5 enqueues and 3 dequeues:

The fix: let the indices wrap around — the slot after MAX − 1 is slot 0.

11.2 · Queue

A circular buffer with MAX = 5

11.2 · Queue

Circular queue: the back is (front + count) % MAX


// static const int MAX = 5;  int data[MAX];  int front = 0, count = 0;
bool enqueue(int x) {
    if (count == MAX) return false;        // full
    data[(front + count) % MAX] = x;       // the back slot
    ++count;
    return true;
}
bool dequeue() {
    if (count == 0) return false;          // empty
    front = (front + 1) % MAX;             // wrap around
    --count;
    return true;
}
  • count tells a full queue from an empty one: with only two indices, both look like front == back.
11.2 · Queue

Linked queue: in at the tail, out at the head


// members: Node* head = nullptr;  Node* tail = nullptr;
void enqueue(int x) {                 // at the back: O(1)
    Node* n = new Node{x, nullptr};
    if (tail) tail->next = n; else head = n;
    tail = n;
}
bool dequeue() {                      // at the front: O(1)
    if (!head) return false;
    Node* old = head;
    head = head->next;
    if (!head) tail = nullptr;        // it was the last node
    delete old;
    return true;
}
  • The reverse fails: removing the tail needs its predecessor, an O(n) walk.
11.2 · Queue

Circular array or linked list: both O(1)

Array + shiftingCircular arrayLinked list (head + tail)
enqueueO(1), fails when fullO(1), fails when fullO(1)
dequeueO(n): shifts n − 1 elementsO(1)O(1)
Capacityfixedfixedonly limited by memory
  • Circular array: no new per element and contiguous memory. Linked list: no capacity to guess in advance.
Checkpoint

A circular queue has MAX = 5, front = 3 and count = 4. In which slot does the next enqueue write?

A. The occupied slots are 3, 4, 0, 1; the next free one is (3 + 4) % 5 = 2. B forgets the modulo: writing data[7] is out of bounds, which is undefined behavior. C is the plain-array thinking the circular buffer fixes: the queue is full only when count == MAX, and here count is 4.

11.3 Deque

11.3 · Deque

A deque opens at both ends

  • A deque (double-ended queue) inserts and removes at the front and at the back: pushFront, pushBack, popFront, popBack.
  • Store it as a doubly linked list with two pointers, front and back: each node knows its prev, so popBack is O(1) too.
11.3 · Deque

popFront has three cases


bool popFront() {
    if (front == nullptr) return false;       // case 1: empty
    DNode* old = front;
    if (front == back) {                      // case 2: one node
        front = back = nullptr;
    } else {                                  // case 3: two or more
        front = front->next;
        front->prev = nullptr;
    }
    delete old;
    return true;
}
  • Case 2 is the one people forget: removing the only node must reset both pointers. popBack is the mirror image (front ↔ back, next ↔ prev).
11.3 · Deque

One deque, two structures

Stack (one end)

  • push → pushFront
  • pop → popFront
  • getTop → getFront

Queue (in at the back, out at the front)

  • enqueue → pushBack
  • dequeue → popFront
  • getFront → getFront

The stack and queue methods become one-line wrappers. The standard library does exactly this: by default, std::stack and std::queue are built on std::deque.

Checkpoint

You delete the if (front == back) branch from popFront. The deque holds exactly one node. What happens on popFront()?

B. With one node, front = front->next makes front nullptr, and the next line writes through it. Even if that line did not crash, back would still point to the deleted node: a dangling pointer. A assumes back is updated, but no line touches it. C confuses one node with zero: only front == nullptr means empty.
Preview · Priority queue

The most urgent leaves first, not the oldest

  • A priority queue stores elements with a priority. insert(x) adds one; extractMin() removes the most urgent one.
  • Arrival order does not matter: the emergency room sees the heart attack before the sprained ankle that arrived an hour earlier.
  • Doing both operations fast needs a new structure, the binary heap, which is a kind of tree. We will build it after trees.
A queue orders by arrival time; a priority queue orders by a key you choose.
Choosing a structure

Choose by who must leave next

ProblemWho leaves nextStructure
Undo, bracket matching, backtrackingthe neweststack
Print jobs, requests to a serverthe oldestqueue
Sliding window, bounded historynewest or oldestdeque

  • Then pick the storage: an array when you know the maximum size, a linked list when you do not.
Checkpoint

A browser keeps the pages you can go Back to; Forward uses a separate list. Back returns to the most recent page, and the history keeps only the last 50 pages: when page 51 arrives, the oldest is dropped. Which structure fits the Back history?

B. The problem needs removals at both ends: the newest page for Back and the oldest one for the limit. A covers Back but cannot drop the bottom of the stack in O(1). C covers the limit but would send Back to the oldest page.

Extra material · self-study

Not covered in class: where these structures live in AI systems, and their STL versions.

Why it matters today

Four access rules inside AI systems

  • Queue: a server that runs a language model keeps incoming requests in a waiting queue; a scheduler decides which ones join the next batch. First-come, first-served is FIFO.
  • Priority queue: beam search keeps only the k best partial answers at each step — a top-k selection, commonly done with a heap.
  • Circular buffer: a reinforcement-learning replay buffer has a fixed capacity and overwrites its oldest experience first — today's circular queue.
  • Stack: reverse-mode automatic differentiation (backpropagation) records operations and then processes them in reverse order: last in, first out.
STL

Container adaptors: an interface over a container

AdaptorOperationsDefault container
std::stackpush, pop, topstd::deque
std::queuepush, pop, front, backstd::deque
  • A container adaptor hides every operation except the allowed ones. You can change the storage: std::stack<int, std::vector<int>>.
  • std::deque itself offers push_front, push_back, pop_front, pop_back in O(1), plus indexing.
STL

Read with top(), then remove with pop()


std::stack<int> s;
s.push(9);
s.push(2);
int x = s.top();    // 1. read the top...
s.pop();            // 2. ...then remove it: pop() returns void
std::cout << x;     // 2
if (!s.empty())
    std::cout << s.top();   // UB if the stack is empty
  • pop() returns void by design: returning the removed element by value could throw during the copy, after the element was already gone.
  • top(), front() or pop() on an empty adaptor is undefined behavior, not an exception. Check empty() first.
