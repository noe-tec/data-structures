The problem

A BST is only as fast as it is short

  • Search, insert and remove follow one path from the root, so they cost O(height). The insertion order decides the height.
  • Sorted input is the worst case: height n − 1, a linked list. The goal for today is a height of O(log n) for every insertion order.

13.1 Balance

13.1 · Balance

AVL: at every node, heights differ by at most 1

  • An AVL tree is a BST where, at every node, the heights of the left and right subtrees differ by at most 1. An empty subtree has height −1.
  • The balance factor of a node is BF = height(right) − height(left). A tree is AVL when every BF is −1, 0 or +1.
  • An insertion can push one node to +2 or −2. The tree repairs itself with a rotation before the insertion returns.
Positive BF: the right side is taller. Negative BF: the left side is taller.

Some books compute left − right. The signs flip; the idea does not.

Checkpoint

A node has a left subtree of height 2 and an empty right subtree. With the definitions of this course, what is its balance factor?

B. BF = height(right) − height(left) = (−1) − 2 = −3. A gives the empty subtree height 0, but that is the height of a single leaf. C has the right size and the wrong sign: with right minus left, a taller left side gives a negative BF.

13.2 · Rotations

A rotation is three pointer changes


// struct AVLNode { int info; int height; AVLNode* left; AVLNode* right; };
// class AVL: member AVLNode* root = nullptr; and these private methods
int height(AVLNode* n) { return n == nullptr ? -1 : n->height; }
int bf(AVLNode* n) { return height(n->right) - height(n->left); }
void update(AVLNode* n) {
    n->height = 1 + std::max(height(n->left), height(n->right));
}
AVLNode* rotateLeft(AVLNode* a) {     // a is right-heavy
    AVLNode* b = a->right;            // b rises
    a->right = b->left;               // T2 changes parent
    b->left = a;                      // a goes down to the left
    update(a);                        // a first: it is now below b
    update(b);
    return b;                         // new root of this subtree
}
  • Stored heights make a rotation O(1). rotateRight is its mirror image.

Checkpoint

An empty AVL tree receives 10 and then 20. Now you insert 15. What does the tree do?

C. BF(10) = +2 and BF(20) = −1: opposite signs, the right-left case, so 15 rises twice and ends with 10 and 20 as its children. A is the right-right fix: here it would leave 20 on top with BF = −2. B forgets that the three nodes form a single path: the left subtree of 10 is empty (height −1) and the right one has height 1, a difference of 2.

13.3 · Insertion

Rebalance: the table, written as code


AVLNode* rebalance(AVLNode* n) {               // private method of AVL
    update(n);
    if (bf(n) == 2) {                          // right-heavy
        if (bf(n->right) < 0)                  // right-left: zig-zag
            n->right = rotateRight(n->right);
        return rotateLeft(n);
    }
    if (bf(n) == -2) {                         // left-heavy
        if (bf(n->left) > 0)                   // left-right: zig-zag
            n->left = rotateLeft(n->left);
        return rotateRight(n);
    }
    return n;                                  // already balanced
}
  • A rotation returns the new subtree root, and the caller stores it.
13.3 · Insertion

AVL insert = BST insert + rebalance on the way up


AVLNode* insert(AVLNode* n, int x) {      // private, recursive
    if (n == nullptr) return new AVLNode{x, 0, nullptr, nullptr};
    if (x < n->info) n->left = insert(n->left, x);
    else if (x > n->info) n->right = insert(n->right, x);
    else return n;                        // repeated value: no change
    return rebalance(n);                  // on the way back up
}
void insert(int x) { root = insert(root, x); }   // public
  • The recursion goes down to insert the leaf, and checks every node of that path while it returns.
  • After an insertion, at most one node needs a fix: one single or one double rotation.

  • Insert 1, 2, 3, …, 1,000,000 in that order: the plain BST has height 999,999 and the AVL tree has height 19.
  • The price: one extra int per node, and a few O(1) rotations.
Checkpoint

You insert one value into an AVL tree that holds a million values. At most how many nodes need a rotation to restore the balance?

A. The rotation gives that subtree the height it had before the insertion, so every node above it is balanced again. B is what the code checks, not what it rotates: rebalance runs at each node of the path, but at most one of them needs a fix. C is true node by node, and that is exactly the problem: a node that was at +1 moves to +2.

Why it matters today

Depth is the price, inside AI systems

  • Decision trees: a prediction follows one path, so it costs the depth of the tree. In an approximately balanced tree trained on n samples, that depth is O(log n).
  • Nearest neighbors: once a k-d tree is built, a query in few dimensions needs about log N distance computations instead of N.
  • Data behind the models: training data often lives in a database, and the default index in PostgreSQL is a B-tree: a search tree with many keys per node that always stays balanced.
STL

std::map: a balanced tree with a value on each key


std::map<std::string, int> count;
for (std::string w : {"tree", "avl", "tree", "bst"})
    ++count[w];                                  // O(log n) each
for (const auto& [word, n] : count)              // keys in ascending order
    std::cout << word << ": " << n << "\n";      // avl: 1  bst: 1  tree: 2
  • count[w] searches for the key and inserts it with the value 0 if it is missing: O(log n) either way.
  • It is usually implemented as a red-black tree, another self-balancing BST: the topic of the next session.
