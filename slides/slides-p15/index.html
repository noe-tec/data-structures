The problem

Sometimes the oldest should not go first

  • A printer: three 1-page jobs wait for a 100-page job that came first.
  • An operating system: an urgent program should not wait its turn.
We need a structure where the most urgent element leaves first.
Priority queue

A priority queue serves the smallest key first

  • Urgency is a number, the key: the smaller the key, the more urgent.
  • In a priority queue the smallest key leaves first, no matter when it arrived.
  • It has three basic operations:
OperationWhat it does
insert(x)adds x
findMin()returns the smallest element, without removing it
deleteMin()removes the smallest element
Choosing a structure

Lists and search trees pay too much

Stored in…insertfindMindeleteMinThe catch
an unsorted listO(1)O(N)O(N)every search scans everything
a sorted listO(N)O(1)O(1)every insert shifts or walks
an AVL treeO(log N)O(log N)O(log N)links, heights, rotations
a binary heapO(log N)O(1)O(log N)none: an array and a counter
The binary heap is the usual way to build a priority queue: it keeps only enough order to find the minimum.

Shape: a heap is a complete binary tree

A complete tree with N nodes has height ⌊log N⌋: about 20 levels for a million nodes.

Order: every parent is smaller than its children

This rule is the heap order. Example from Weiss (2014), Fig. 6.5.

15.1 · Structure and order

Min-heap or max-heap: flip one comparison

  • Same six values, two heaps. We follow Weiss: a min-heap, with findMin and deleteMin.
  • A heap is not sorted: siblings are in no order, and the maximum of a min-heap can be in any leaf.
Checkpoint

A heap of N = 30 elements is stored from cell 1. A node is in cell 13. Where are its parent and its children?

B. The children of i are 2i = 26 and 2i + 1 = 27, both ≤ 30, so both exist. The parent is 13 / 2 = 6: integer division rounds down. A rounds 6.5 up. In C++, 13 / 2 is 6, and the formula must give the same parent, 6, for its two children, 12 and 13. C takes the next cells as children. Cells 14 and 15 are the children of 7, the sibling of 6.

15.2 insert and deleteMin

Each one breaks a property for a moment, then repairs it along one path.

15.2 · insert and deleteMin

insert: open a hole at the end and move it up

Example from Weiss (2014), Fig. 6.6–6.7. This is a percolate up.

15.2 · insert and deleteMin

insert in code: slide the parents, do not swap


void insert(int x) {
    if (currentSize == int(array.size()) - 1)
        array.resize(array.size() * 2);          // full: double it
    // Percolate up (hole > 1: stop at the root)
    int hole = ++currentSize;                    // a hole at the end
    for (; hole > 1 && x < array[hole / 2]; hole /= 2)
        array[hole] = array[hole / 2];           // parent slides down
    array[hole] = x;                             // x fits here
}
  • x waits outside while each greater parent slides down into the hole: d levels cost d + 1 assignments; d swaps would cost 3d.
  • Worst: O(log N), a new minimum climbs to the root. Average: 2.607 comparisons, O(1).
Checkpoint

You run insert(5) on the min-heap [10, 20, 15, 30, 40], in cells 1 to 5. Where does 5 end up?

A. The hole opens in cell 6. Its parent, cell 3, holds 15 > 5: 15 slides down. The hole is now in cell 3, whose parent, cell 1, holds 10 > 5: 10 slides down. The hole is the root, so 5 goes there: [5, 20, 10, 30, 40, 15]. B stops after the first step. Cell 6 is where the hole starts, and 5 can stay there only if it is not smaller than its parent. C moves the whole array, like an insertion into a sorted array, which costs O(N). The heap moves only the cells on one path: O(log N).

deleteMin: the last element fills the root, then sinks

Example from Weiss (2014), Fig. 6.9–6.11. This is a percolate down.

15.2 · insert and deleteMin

findMin and deleteMin in code

findMin reads the root; deleteMin removes it.


const int& findMin() const {
    if (isEmpty()) throw std::underflow_error("empty heap");
    return array[1];
}
void deleteMin() {
    if (isEmpty()) throw std::underflow_error("empty heap");
    array[1] = array[currentSize--];             // the last one goes up
    percolateDown(1);
}
  • The last element moves to the root, and currentSize-- takes its old cell out of the heap. The tree stays complete.
15.2 · insert and deleteMin

percolateDown: follow the smaller child

When N is even, one node has only a left child: minChild checks that the right one exists.


int minChild(int i) const {       // smaller child of i; > currentSize if leaf
    int child = 2 * i;
    if (child < currentSize && array[child + 1] < array[child]) ++child;
    return child;
}
void percolateDown(int hole) {
    int tmp = array[hole];                       // the value that sinks
    int child = minChild(hole);
    while (child <= currentSize && array[child] < tmp) {
        array[hole] = array[child];              // child slides up
        hole = child;
        child = minChild(hole);
    }
    array[hole] = tmp;
}
Checkpoint

A student deletes child < currentSize && from minChild, then builds a heap from {8, 5, 17, 3}. What happens?

C. With N = 4, cell 2 has only a left child, in cell 4. minChild(2) still reads array[5], an unused cell that holds 0, and returns 5. The while sees 5 > 4 and stops too early, so 3 never goes up. We ran it: the result is 5 8 17 3. A: the while checks the child that minChild returns, but by then minChild has already chosen the wrong one. B: the vector has 4 + 10 cells, so array[5] is a legal read. No crash, only a wrong heap, and that is worse: nothing warns you.
15.2 · insert and deleteMin

Fast at the root, blind everywhere else

OperationWorst caseWhy
findMinO(1)the minimum is always in array[1]
insertO(log N)one path up; O(1) on average
deleteMinO(log N)one path down, almost to the bottom on average
find any xO(N)x could be anywhere below a smaller key
  • If you need to search for any key, use a search tree or a hash table, not a heap.

15.3 buildHeap

N values at once: faster than N inserts.

15.3 · buildHeap

buildHeap: fix the order from the last parent up

The leaves are already heaps. Fix each parent, from the last one (cell N/2) up to the root.

Example from Weiss (2014), Fig. 6.15–6.18.

15.3 · buildHeap

buildHeap in code


explicit BinaryHeap(const std::vector<int>& items)
    : currentSize{int(items.size())}, array(items.size() + 10) {
    for (int i = 0; i < currentSize; ++i)
        array[i + 1] = items[i];                 // any order: still complete
    buildHeap();
}
void buildHeap() {
    for (int i = currentSize / 2; i > 0; --i)    // the last parent first
        percolateDown(i);
}
15.3 · buildHeap

buildHeap is O(N): most nodes are near the bottom

A node can sink at most as many levels as its height. In the tree of 15 nodes:

HeightNodesWork (nodes × height)
0 (the leaves)88 × 0 = 0
144 × 1 = 4
222 × 2 = 4
3 (the root)11 × 3 = 3
Total1511 levels, less than N
The total is always less than N: buildHeap is O(N).

Perfect tree of height h: sum of heights \( = 2^{h+1} - 1 - (h+1) < N \) (Weiss, Theorem 6.1).

STL

std::priority_queue is a max-heap by default


std::priority_queue<int> maxPQ;                             // max-heap: the default
std::priority_queue<int, std::vector<int>, std::greater<int>> minPQ;
for (int x : {4, 3, 5}) { maxPQ.push(x); minPQ.push(x); }
while (!minPQ.empty()) { std::cout << minPQ.top() << ' '; minPQ.pop(); }
std::cout << '\n';                                         // 3 4 5
while (!maxPQ.empty()) { std::cout << maxPQ.top() << ' '; maxPQ.pop(); }
std::cout << '\n';                                         // 5 4 3
  • push, top, pop work on the largest element; std::greater<int> makes it a min-heap.
  • Header <queue>. The heap lives in a std::vector, with the root in cell 0.
Self-study

Other kinds of heaps

  • d-heaps: d children per node, so the tree is shallower. insert gets cheaper; deleteMin must find the smallest of d children. 4-heaps may beat binary heaps in practice.
  • Leftist and skew heaps: linked trees that can merge two heaps in O(log N). Merging two array heaps costs Θ(N).
  • Binomial queues: a forest of trees; merge in O(log N), insert in O(1) on average.
  • Heapsort: buildHeap, then N deleteMins, in the same array: O(N log N) with O(1) extra memory.

To go further: Weiss (2014), chapter 6, and § 7.5 for heapsort.

Why it matters today

Heaps inside AI systems

  • Finding the closest documents: FAISS, Meta's library for vector search, keeps the best k results of a search in a heap. Its heap_pop uses 1-based cells "for easier node->child translation" and slides values into a hole, like these slides.
  • Serving language models: in vLLM, an open-source server for language models, the priority policy keeps waiting requests in a heap: the lowest priority value goes first, and ties go to the earliest arrival.
Challenge · at home

Two problems that want a heap

LC 703 — Kth Largest Element in a Stream [Easy] · optional

Scores arrive one by one; after each one, report the k-th largest so far. Keep a min-heap with only k elements: its root is the answer.

LC 295 — Find Median from Data Stream [Hard] · optional

Numbers arrive; report the median at any moment. Hint: two heaps, a max-heap for the smaller half and a min-heap for the larger half.

You may use std::priority_queue or your own BinaryHeap. No sorting after each new value.
