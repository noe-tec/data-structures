The problem

Trees are not enough

  • In a tree, each node has one parent.
  • Roads and friendships are many-to-many: Mty links to four cities.
  • There can be many routes, and some go in circles.
A graph is the most general linked structure: any element may connect to any other.

16.1 What a graph is

Two sets, and a few words to talk about them.

16.1 · What a graph is

A graph is a set of vertices and a set of edges

\[ G = (\mathcal{V}, \mathcal{E}), \qquad \mathcal{E} \subseteq \mathcal{V} \times \mathcal{V} \]
  • Vertices (nodes): the cities. V = 8.
  • Edges (arcs): pairs, like (Lar, Mty). E = 11 roads.
  • w is adjacent to v if \( (v, w) \in \mathcal{E} \). Mty's neighbors: Lar, Rey, Sal, Vic.
  • Mty has 4 neighbors: its degree is deg(Mty) = 4.

\( \mathcal{V} \) and \( \mathcal{E} \) are the sets. V and E, in plain letters, are their sizes: V = 8, E = 11.

16.1 · What a graph is

Direction and weight change what an edge means

  • Directed: one-way, like a one-way street from A to B.
  • Weighted: each edge has a cost: km, minutes, pesos.

16.1 · What a graph is

Complete graph: an edge between every pair

  • 4 vertices, 4 · 3 / 2 = 6 edges: the maximum of the table.
  • Much stronger than connected: connected only needs a path.
16.1 · What a graph is

Dense or sparse?

Dense: E = Θ(V²), near the maximum.

Sparse: E = O(V), far below it.

Most real graphs are sparse: that decides how we store them.
Checkpoint

In an undirected graph with the edge (u, v), is u, v, u a cycle?

B. Correct. In an undirected graph (u, v) and (v, u) are the same edge, and a cycle must use distinct edges. Otherwise every edge would make a cycle.

A. Ending where it starts is necessary, not enough. In a directed graph with both u → v and v → u, it would be a cycle: those are two different edges.

C. A weight adds information to an edge; it does not turn one edge into two.

16.2 · Adjacency matrix

The matrix in code: one cell per pair


class MatrixGraph {                        // vertices 1..n, as in Weiss
    int n;
    std::vector<std::vector<bool>> adj;    // adj[u][v]: is there an edge u -> v?
public:
    explicit MatrixGraph(int n) : n{n}, adj(n + 1, std::vector<bool>(n + 1, false)) {}
    void addEdge(int u, int v) { adj[u][v] = true; }          // O(1)
    bool hasEdge(int u, int v) const { return adj[u][v]; }    // O(1)
    std::vector<int> neighbors(int u) const {                 // Θ(V): reads the whole row
        std::vector<int> out;
        for (int v = 1; v <= n; ++v)
            if (adj[u][v]) out.push_back(v);
        return out;
    }
};

Vertices go from 1 to n, as in Weiss: row 0 and column 0 stay empty.

16.2 · Adjacency matrix

A column answers "who points to me?"

A directed graph: Weiss (2014), Fig. 9.1. Row u gives out-deg(u): out-deg(4) = 3. Column v gives in-deg(v): in-deg(6) = 3. Each costs Θ(V).

Checkpoint

An undirected graph has V = 1,000 vertices and E = 3,000 edges. In its V × V adjacency matrix, how many cells are true?

A. Correct. Each undirected edge sets two cells, adj[u][v] and adj[v][u]: 2 × 3,000 = 6,000.

B. That would be right for a directed graph, where each edge sets one cell.

C. Confuses the memory with the content: the matrix has 1,000,000 cells, but most of them hold false.

16.3 · Adjacency list

The list in code, using a vector of vectors


class ListGraph {                          // vertices 1..n, undirected
    std::vector<std::vector<int>> adj;     // adj[u]: the vertices adjacent to u
public:
    explicit ListGraph(int n) : adj(n + 1) {}
    void addEdge(int u, int v) {           // O(1) amortized
        adj[u].push_back(v);               // v goes in the list of u
        adj[v].push_back(u);               // and u in the list of v
    }
    bool hasEdge(int u, int v) const {     // O(deg(u))
        for (int w : adj[u]) if (w == v) return true;
        return false;
    }
    const std::vector<int>& neighbors(int u) const { return adj[u]; }
};

Weiss: vectors or linked lists both work, at the same cost.

16.3 · Adjacency list

Directed: each edge goes in one list


// Directed: the edge u -> v goes only in the list of u
void addEdge(int u, int v) {               // O(1) amortized
    adj[u].push_back(v);                   // no adj[v].push_back(u)
}
  • Directed: E edges, E entries. Undirected: 2E. Both Θ(V + E).
  • Weighted: each entry is a pair (neighbor, cost).
    • Type: vector<vector<pair<int, int>>>
    • Lar: (Mty, 3), (Rey, 5)

You need every vertex with an edge into 6. What is the time complexity?

16.4 · Edge list

The edge list in code


struct Edge { int from, to; };
class EdgeListGraph {
    std::vector<Edge> edges;               // one entry per edge, in any order
public:
    void addEdge(int u, int v) { edges.push_back({u, v}); }   // O(1) amortized
    bool hasEdge(int u, int v) const {                        // O(E): scan them all
        for (const Edge& e : edges)
            if (e.from == u && e.to == v) return true;
        return false;
    }
};
  • Use it when you need the edges, not the neighbors: sort them by weight.

16.5 · Arc lists

Arc lists in code: one node, two links


struct Arc {
    int from, to;
    Arc* nextOut;                          // next arc that leaves `from`
    Arc* nextIn;                           // next arc that enters `to`
};
struct Vertex { Arc* out = nullptr; Arc* in = nullptr; };

void addArc(std::vector<Vertex>& g, int u, int v) {     // O(1)
    Arc* a = new Arc{u, v, g[u].out, g[v].in};           // one node, two lists
    g[u].out = a;                                        // push it on u's out-list
    g[v].in = a;                                         // and on v's in-list
}
  • Out-list of u: O(out-deg(u)). In-list of v: O(in-deg(v)). Price: two pointers per arc.

Checkpoint

A network has 2,000 routers, and almost every pair is directly linked. A program asks "are u and v linked?" millions of times. Which representation fits best?

B. Correct. With E = Θ(V²), the matrix costs no more memory than the lists, and it answers each question in O(1).

A. "Always" is false: for a dense graph Θ(V + E) = Θ(V²), and each question costs O(deg(u)), about 2,000 steps.

C. Its memory is fine, but each question scans all the edges: O(E), about 2,000,000 steps.
