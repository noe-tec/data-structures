Starting point

An AVL tree works hard to stay short

  • An AVL tree stores a height in every node, and after each insertion it checks the balance on the whole path back to the root.
  • A red-black tree stores just one bit per node, a color, and accepts a slightly taller tree: still O(log N) in the worst case.
  • In exchange, an insertion repairs the tree with at most two rotations; the rest is changing colors.
  • It is the tree behind GCC's std::set and std::map, Java's TreeMap, and many parts of the Linux kernel.
Balance is a rule about colors, not about heights: keep the colors right and the height takes care of itself.

E1.1 The four rules

What makes a BST a red-black tree, and why it can never get too tall.

E1.1 · The four rules

One color per node, four rules

The four rules as in Weiss (2014), § 12.2. Cormen et al. (2009) state five, because they also count the null links as black leaves.

Checkpoint

A red node has exactly one child, and that child is black. Can this happen in a red-black tree?

B. From the red node, the path down the null side counts 0 black nodes, and the path through the black child counts at least 1. Rule 4 needs both counts equal. A checks rule 3 only; rule 3 does hold here, but every rule must hold at once. C cannot happen: rule 2 says the root is black. In fact, a red node has either no children or two black ones.
E1.1 · The four rules

Why the height stays O(log N)

  • Call b the black height of the root: the number of black nodes on every path from the root down to a null link (rule 4). In Fig. 12.9, b = 3.
  • Shortest path: at least b nodes, all of them black. So the first b levels are full, and N ≥ 2b − 1, that is, b ≤ log(N + 1).
  • Longest path: reds never come two in a row (rule 3), so at most one red after each black: at most 2b nodes.
The longest path holds at most 2b ≤ 2 log(N + 1) nodes: the height is at most 2 log(N + 1), so every search is O(log N).

Weiss (2014), § 12.2; the full proof is Lemma 13.1 in Cormen et al. (2009).

Checkpoint

Every path from the root of a red-black tree to a null link has 3 black nodes. At most, how many nodes can the longest such path have?

B. The root is black, and after each black node there can be at most one red one: black, red, black, red, black, red. That is 2 · 3 = 6 nodes. A is the shortest possible path, one with only black nodes. C would need two red nodes after each black one, and rule 3 forbids two reds in a row.

E1.2 Insertion

Insert as in a BST, color the node red, then repair from the bottom up.

E1.2 · Insertion

The new node is always red

Why red: a black node would add a black node to the paths through it only, and break rule 4 every time. A red node can only break rule 3, and only when its parent is red.

E1.2 · Insertion

Red parent: look at the parent's sibling

  • We name the nodes as Weiss does: X is the new node, P its parent, G its grandparent, and S the sibling of P, the other child of G.
  • If P is red, X and P are two reds in a row: rule 3 broke. G exists and is black, because P is red and cannot be the root.
  • The repair depends on the color of S. A null S counts as black.
S red: change colors only. S black: rotate, as in an AVL tree, then recolor.

Checkpoint

X is the right child of P, P is the left child of G, both X and P are red, and S is null. What fixes the tree?

C. A null S counts as black, so it takes rotations; and the path G → P → X bends (left, then right), so it takes two, as with insert(8). A is the repair for a red S; with a null S there is no node to turn black. B is the repair for a straight line. Here it would leave X as the left child of G, still red under a red G.

Checkpoint

After a color flip, G is red and the parent of G is red too. What happens next?

A. The flip kept every black count, but it may leave two reds in a row higher up. The repair continues with X = G: look at its parent and the sibling of that parent, as in insert(45). B is true only when the parent of G is black, as in insert(79), or when G is the root, which turns black. C is never needed: the flip was correct; it only moved the problem up.
AVL vs red-black

Two ways to stay O(log N)

AVL treeRed-black tree
Extra data per nodeits heightone bit: its color
Height, worst caseabout 1.44 log N (28 levels for N = 106)2 log(N + 1) (40 levels for N = 106)
Rotations per insertionat most 2 (one single or one double)at most 2
Rotations per deletionmay be needed at every level of the pathat most 3
An AVL tree is shorter, so searches are a bit faster. A red-black tree changes less on each update: that is the trade GCC, Java and Linux chose.

AVL bound: 1.44 log(N + 2) − 1.328, Weiss (2014), § 4.4. The Linux kernel documentation makes the same comparison: faster bounded insertions and deletions, slightly slower but still O(log n) lookups.

E1 · Common pitfalls

Mistakes to watch for

  • Coloring the new node black. It breaks rule 4 every time. New nodes are red.
  • Forgetting that null counts as black. If P has no sibling, S is black: rotate, do not flip.
  • Rotating when S is red. A red S needs a color flip only; after a rotation, G would turn red right above the red S.
  • Stopping after a flip. Check the parent of G: if it is red, repeat at G. If G is the root, turn it black.
  • Rotating without recoloring. After the rotation, the node on top turns black and G turns red.
